# Эквайринг доставленных отправлений

Рабочая основа: fix/ads-carts-report, 8665a1e786f0bfb94e9c871a15998eb9dc95fb96. Корзины рекламы и исправление даты доставки сохранены. Новая ветка: fix/delivered-acquiring. main не изменяется.

## Что изменено

1. Для доставленных отправлений эквайринг ищется в подтверждённых начислениях, а при его отсутствии — в /v3/finance/transaction/list по типу MarketplaceRedistributionOfAcquiringOperation.
2. Убрана попытка передавать родительский номер заказа в /v1/finance/accrual/postings: этот метод ожидает полный номер отправления и может отвергать номер заказа без суффикса.
3. Интервалы транзакций строятся по дате из независимо проверенного ответа FBS, помесячно, до текущего времени. Произвольная дата клиента не управляет поиском. Автоматический поиск ограничен недавними заказами (до 93 дней), покрывающими рабочую историю списка.
4. Из транзакций выбираются только эквайринг и точные номера текущего отправления/его заказа. Проценты комиссии не придумываются.
5. Общая комиссия заказа включается только при явном отсутствии связанных отправлений/родительского разбиения в ответе FBS и совпадении SKU операции с товарами текущего отправления. При неизвестном распределении или разбиении её нельзя вычесть целиком из каждого отправления: показано пояснение и нет добавленного списания.
6. Дубли operation_id исключены; конфликтующие операции и возможное пересечение с уже учтённым начислением не вычитаются повторно. Сохранён исходный знак: отрицательное списание уменьшает остаток, положительный возврат увеличивает его.
7. В карточке появилась строка «Эквайринг (в расходах Ozon)». Это расшифровка уже включённой суммы, а не дополнительное повторное вычитание. Общие расходы и «После удержаний» считают операцию один раз.
8. Отсутствие комиссии не считается нулём. Ошибка дополнительного метода не скрывает уже полученные начисления. Нераспределённая комиссия и ограничение Ozon объясняются отдельно.

## Кеш и ограничения запросов

Обнаружено, что server-side financeCache, кеш проверки доставки, справочник типов и cooldown ранее объявлялись внутри обработчика HTTP, то есть создавались заново при каждом запросе. Они перенесены в область модуля. Подтверждённый результат используется повторно; пауза после 429 сохраняется между запросами.

localStorage-ключи и прежние сохранённые начисления не удаляются. Записи без метаданных проверки эквайринга остаются видимыми и постепенно обновляются. Новые записи содержат acquiring_version=2 и статус проверки; после перезагрузки подтверждённые записи используются повторно. Отсутствующий эквайринг допускает повторную проверку после 10 минут, с сохранением существующей защиты от 429. Кеш, уже дополненный эквайрингом, сохраняет существующие длительные правила хранения.

## Без изменений

Статус «Доставлен» подтверждается на backend. Для недоставленных финансовый маршрут остаётся закрыт. Сохраняются авторизация, точные CORS-origin, дата вручения из отчёта и её МСК-отображение, список и фильтр «В пути», реклама с корзинами. Никаких изменений заказов, ставок, цен, остатков, выплат или иных бизнес-данных Ozon не добавлено. Все внешние POST используются только для методов чтения.

## Статус

Это подготовленное исправление. Развёртывание и проверка суммы эквайринга на реальном доставленном отправлении ещё не выполнены. Требуется отдельное разрешение на публикацию backend и интерфейса из этой ветки без изменения main. При живой проверке возможны ограничения Seller API 429 или отсутствие распределения общей комиссии; в этих случаях нельзя показывать выдуманное списание.

Backend и интерфейс 68b04bc запущены. Живую проверку финансов временно блокирует сохранённая пауза после ответа Ozon 429. В интерфейсе добавлено явное сообщение о времени возобновления проверки по Москве; пауза не сбрасывается и лишние запросы не отправляются. Проверка суммы на живом отправлении пока не завершена.
