# Полный журнал начислений Ozon и корректировки прибыли

База: установленный main `21c4607cabac0d15e4ef3185aad930b0b386f389`.
Ветка: `work/finance-ledger-2026-10-27`. Подготовлено 27.10.2026, без публикации.

## Что реализовано

- Авторизованный GET `/api/finance/ledger?date=YYYY-MM-DD`: все доступные начисления одного дня через официальный `/v1/finance/accrual/by-day`, полная пагинация, словарь `/types`, суммы в целых копейках, сверка итога с детализацией.
- Общие расходы без отправления: плата за услуги выплат, штрафы, компенсации покупателям, подписки, складские услуги, вывоз, утилизация, корректировки. Знаки источника сохранены; компенсации продавцу не теряются.
- Отдельный журнал в «Аналитика → Финансы»: категории, статус каждой строки, источник, даты, полнота, дополнительное влияние на прибыль. Из детализации прибыли/расходов главной есть переход в этот раздел.
- Главная и аналитика учитывают только дополнительные суммы поверх существующей экономики доставок. Итоги отправлений с выручкой повторно не прибавляются. Неоднозначные пересечения блокируют окончательный результат.
- Эквайринг сверяется с уже учтёнными строками, включая подтверждённую привязку родительского номера. Движения денег не становятся расходами. Реклама остаётся по точному периоду Performance; её начисления видны, но повторно не вычитаются.
- Неизвестный тип не определяется как расход только по отрицательному знаку. Доступно локальное назначение категории для конкретного ID типа с отменой назначения.
- Возврат выручки учитывается со знаком; изменение себестоимости требует явного ручного подтверждения. Подтверждение связано с исходной строкой и перестаёт действовать при изменении её реквизитов/суммы. История себестоимости товара не меняется.
- Кэш по дням на сервере и устройстве, сохранение прежнего успешного результата при сбоях, ограниченная история пересмотров. Фоново обновляются до трёх уже загруженных устаревших дней выбранного периода; первоначальная загрузка начинается кнопкой. Ограничения Ozon и последовательная очередь сохранены.
- При смене источника на другой магазин загрузка останавливается: прежние данные не удаляются и не смешиваются.
- CSV: чтение в браузере, явное сопоставление колонок, предварительная проверка, подтверждение полного периода и импорта, точные ID, защита от конфликтов и повторного учёта. Экспорт журнала нейтрализует формулы. Содержимое файла не передаётся Ozon или backend.

## Важные границы расчёта

Это экономика доставленных заказов с дополнительными начислениями периода, а не полноценный бухгалтерский отчёт о прибыли по дате начисления каждой продажи. Оба представления показаны отдельно: исходная экономика доставок и журнал/влияние корректировок. Нельзя механически суммировать выручку заказов и net-итоги отправлений.

Составные итоги POSTING вне доставок выбранного периода показываются, но не превращаются автоматически в расходы: внутри могут быть продажи и возвраты. До сверки итог остаётся предварительным. Неизвестные типы, неоднозначные дубли, пропущенные дни, устаревшие данные и неподтверждённая себестоимость возвратов также препятствуют объявлению полного результата. Неизвестные суммы не считаются нулевыми.

Ручное назначение категории и подтверждение себестоимости влияют на локальную аналитику; они не являются операциями Ozon. Проверяйте назначение по официальным документам. Прочие вручную введённые расходы сохраняются: уже записанные вручную комиссии/штрафы нужно отдельно сверить с журналом, поскольку у них нет ID операции для автоматического сопоставления.

CSV поддерживает UTF-8, даты YYYY-MM-DD или DD.MM.YYYY, числовые ID начислений/типов и суммы RUB со знаком. При отсутствии уникальных ID или при неоднозначной многострочной детализации импорт отклоняется. XLSX/макросы не исполняются; исходный официальный XLSX можно сохранить в CSV со значениями. Схема конкретной реальной выгрузки ещё не проверена.

## Проверки

95 автоматических тестов прошли. Проверены знаки начислений, платы за выплаты отдельно от тела перевода, положительные корректировки, эквайринг без дублей, родительские/неоднозначные операции, поздние удержания, возвраты и отмена подтверждений при изменениях, CSV, повреждённый кэш, московская полночь, пагинация, ошибки доступа, 429, auth/CORS/GET-only и защита от выдачи секретов.

Отдельный интеграционный тест с включённым HTTP-кэшем прошёл: 390 → 240 после штрафа/возврата, 340 после подтверждённого восстановления себестоимости, 390 после явной переклассификации штрафа в движение денег. Это тестовые значения, не данные магазина.

Регрессии старых UI-тестов проверены с test-dom-compat.cjs; реальные Request/Response и кэш отдельно проверены без этого helper. Синтаксис JS и git diff --check прошли.

## Что ещё не подтверждено

Реальные ответы нового метода для подключённого магазина, соответствие всех типов начислений, схема официального файла, сверка с закрытым отчётом Ozon и мобильная визуальная приёмка. Код протестирован на фикстурах. Неподдержанный/неполный ответ не публикуется как успешная нулевая выгрузка.

Налоги остаются исключёнными. Основные формулы product-analytics.js и dashboard-model*.js, repricer, история затрат и разрешения рекламного управления не менялись. Доступны только два прежних origin; добавлен один GET-маршрут. Никаких новых операций записи в Ozon.

## Установка

Сначала установить backend вместе с finance-ledger.js и finance-ledger-reader.js, сохранив существующие переменные окружения. Затем фронтенд. Для новых JS/CSS добавлены версии ресурсов. Старый backend вернёт 404: интерфейс покажет необходимость обновить сервер и сохранит предварительный результат.

До публикации проверить новый endpoint для одного дня, сверить ID/суммы с официальным отчётом, затем закрытый период и мобильную вёрстку. Публикация требует отдельного разрешения пользователя. Откат — отмена отдельного коммита; не очищать localStorage с себестоимостью.

Тесты (Node 22+, jsdom через NODE_PATH):
`node --require ./test-dom-compat.cjs --test --test-force-exit '*.test.cjs'`
`node --test --test-force-exit finance-ledger-ui.test.cjs`
