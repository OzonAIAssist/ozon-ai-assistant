# Ozon AI Assistant v0.1

Рабочий локальный демонстрационный прототип помощника для CPC-рекламы Ozon с обязательным подтверждением изменений.

## Запуск

Требуется Python 3.10+.

```bash
python -m venv .venv
# Linux/macOS: source .venv/bin/activate
# Windows: .venv\Scripts\activate
pip install -r requirements.txt
uvicorn main:app --host 127.0.0.1 --port 8000
```

Откройте http://127.0.0.1:8000 . Для API-документации: http://127.0.0.1:8000/docs .

## Сценарий проверки

1. Нажать «Сформировать рекомендации».
2. Просмотреть причину, старую и новую ставки.
3. Одобрить или отклонить каждую рекомендацию.
4. Убедиться, что одобренная ставка изменилась в таблице товаров, а отклонённая — нет.
5. Проверить журнал событий.

## Принципы и ограничения

- Только демо-данные. Нет соединения с Ozon, нет фоновых заданий, нет реальных API-вызовов.
- Под «ИИ» в v0.1 подразумевается **детерминированный рекомендательный алгоритм**, а не подключённая LLM.
- ДРР = расход на рекламу / атрибутированная рекламная выручка × 100%.
- Порог ДРР для демонстрации = 70% от введённой доли маржи. Это упрощение, **не** полноценная юнит-экономика.
- Алгоритм снижает ставку на 10% при превышении порога; на 15% при расходах без выручки; повышает на 5% при достаточно низком ДРР и от 100 кликов. Меняет только локальную демо-ставку.
- Исторические клики, расходы и выручка не меняются после локального изменения ставки; поэтому повторный анализ может предлагать дальнейшую корректировку на старой статистике. В production нужны свежие периоды, лимиты частоты и проверка статистической надёжности.
- Запускайте только локально. В прототипе отсутствуют авторизация, CSRF-защита, контроль ролей, секрет-хранилище и production-безопасность.
- Для реального Ozon Performance API необходимо отдельно проверить актуальные методы, права, ограничения ставок и требования к авторизации, реализовать безопасный адаптер и подтверждение конкретного изменения перед отправкой.

## План v0.2

1. Импорт CSV реальных рекламных отчётов.
2. Ввод себестоимости, комиссий, логистики и возвратов для расчёта допустимого ДРР.
3. Защита от повторных решений на старой статистике и минимальный объём данных.
4. Подключение API только после проверки текущей документации и доступа.
5. Авторизация, аудит, резервные копии и защита от повторной отправки команд.

## v0.2: автопилот (демонстрационный)

После запуска откройте http://127.0.0.1:8000/autopilot .
Установите дневной и недельный бюджеты, границы ставки, интенсивность показов и стратегию. Настройки сохраняются в SQLite. Введите тестовые расходы, час и день недели, затем нажмите «Рассчитать ставки».

Это только симулятор одного шага: нет фонового планировщика, фактической почасовой статистики, интеграции с Ozon, остановки кампаний и гарантированного соблюдения бюджета. Для реального автоматического управления необходимы API-доступ, проверка допустимых операций и ограничений кампаний, учёт задержек статистики, журналирование и аварийная остановка.

## v0.3: расписание для нескольких кампаний

Откройте `/schedules`. Для каждой кампании отдельно задаются ID, имя, часовой пояс IANA, дни недели, время включения и выключения. Сохранение в SQLite: `PUT /api/campaign-schedules/{campaign_id}`; просмотр: `GET /api/campaign-schedules`; вычисление желаемого состояния: `GET /api/campaign-schedules/status`. Можно задать несколько временных окон через API. Интервалы, переходящие через полночь, поддерживаются. Начало включительно, конец исключительно; равные времена означают полные сутки для выбранного дня.

**Ограничение:** это только конфигурация и расчёт желаемого состояния по запросу. Фонового планировщика и подключения Ozon API нет, реклама реально не выключается. Для боевого режима необходимы поддерживаемые методы Ozon Performance API, фоновый worker, сверка фактического состояния, повторные попытки, защита от ошибок и управление доступами. Часовой пояс задавайте явно.

## v0.4 — Историческая аналитика

После запуска откройте `/analytics`. Импортируйте `sample_analytics.csv` для примера или свой UTF-8 CSV с заголовками `date,campaign_id,campaign_name,impressions,clicks,spend,orders,revenue`. Дата в формате YYYY-MM-DD, одна строка на кампанию и день. Импорт атомарный, повторные записи заменяются. Данные хранятся в SQLite, можно фильтровать кампании, смотреть 7/30/90/365 последних дат и графики по расходам, выручке, показам, кликам, заказам, ДРР, CTR, CPC. API: `POST /api/analytics/import` (multipart file) и `GET /api/analytics?days=30&campaign_id=101`. Это **не автоматический сбор из Ozon**: интеграция с Ozon Performance API и фоновый сбор — отдельный этап. Файл примера вымышленный. Для реальных данных нужна адаптация формата выгрузки Ozon к схеме импорта.


## v0.5 Почасовая аналитика
Откройте `/hourly`. Импортируйте `sample_hourly.csv` или собственный CSV с колонками date,hour,campaign_id,campaign_name,impressions,clicks,spend,orders,revenue. Часы должны быть в едином часовом поясе. Нет автоматического сбора из Ozon, а почасовые данные не следует выводить из дневных отчётов.
